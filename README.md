# CS 405 Secure Coding Portfolio

This repository contains some of the work I completed throughout CS 405 Secure Coding. During this course, I learned that writing secure code involves more than making sure a program works correctly. Developers also have to think about possible vulnerabilities, how someone could misuse a program, and how sensitive information can be protected.

## Project One: Security Policy

For Project One, I created a security policy for Green Pace. This project helped me understand how secure coding standards can be used to identify and prioritize security risks. I looked at areas such as input validation, SQL injection, memory protection, integer safety, and pointer safety. I also considered the severity, likelihood, and cost of fixing different vulnerabilities.

## Project Two: Security Policy Presentation

For Project Two, I used the work from Project One to create a security policy presentation. I discussed defense in depth, secure coding standards, encryption, authentication, authorization, accounting, unit testing, and security automation. This project helped me see how different security practices can work together instead of depending on only one layer of protection.

## Coding Projects

This repository also includes coding activities that I completed during the course. Some of these activities include:

- SQL injection prevention
- Buffer overflow prevention
- Exception handling
- Encryption
- Static analysis
- Unit testing

These activities gave me experience finding security problems and making changes to improve the security of C++ programs. I also worked with tools such as Visual Studio, Cppcheck, and Google Test.

## What I Learned

One of the biggest things I learned from this course is that security should not be left until the end of development. It should be considered while software is being designed, written, and tested. I also learned the importance of evaluating risk, following secure coding standards, using multiple layers of security, and testing code for both expected and unexpected situations.

Going forward, I will try to think about security from the beginning when developing software instead of only asking whether my code works. I will also think about what could go wrong and what I can do to make the program safer.
